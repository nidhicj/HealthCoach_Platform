# PHASE-01d — Meeting Link (HC-side) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the HC attach a meeting link (Google Meet/Zoom/anything) to a session, either when creating it or any time after, and show a real "Join call" button on the session page. This is F6's HC-side only (SPEC-0001 D-28) — the client-facing half is deliberately deferred until the client app's own navigation structure exists.

**Architecture:** One new nullable column on the existing `sessions` table. The existing `create_session`/`patch_session` endpoints both already accept partial updates to the `Session` row — this just adds one more optional field to each. On the frontend, the "New session" form gets one more optional input, and the session page's existing "Google Meet placeholder" block (currently a disabled "Join (coming soon)" span) becomes a real, live-editable field with a working link.

**Tech Stack:** Same as the rest of Unit_004 — FastAPI/SQLAlchemy backend, Next.js/TypeScript frontend, Alembic migrations. No new dependencies.

## Global Constraints

- Python ≥ 3.12, FastAPI ≥ 0.115, SQLAlchemy ≥ 2.0, Pydantic ≥ 2.7
- Tests hit a real PostgreSQL DB (`parivarthan_test`) — no mocking the DB
- Activate the Python env with `source /mnt/hdd/yourProjects/venv/hc_pf/bin/activate` before running backend commands
- Basic URL validation only (must look like a URL) — no platform-specific detection (Zoom vs. Meet vs. anything else) needed
- Editable at any time, no locking — this is not part of the Freeze/Send-style "coach-reviewed gate" pattern used elsewhere in this unit; a meeting link is just logistics, not client-facing content requiring review
- No client-facing routes/UI in this phase — HC-side only (D-28)

        meeting_url: meetingUrlRaw || undefined,
      });
